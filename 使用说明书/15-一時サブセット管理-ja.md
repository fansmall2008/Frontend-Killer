# 15 · 一時サブセット管理

> 一時サブセット（ゲームサブセット）は、あるプラットフォームから「条件で抽出した一握りのゲーム」の一時的な集まりです。まず条件でゲームを囲い込み、1 つずつ編集し、編集後にメインセットへ同期するか、別名で新プラットフォームとして保存するかを決められます。本章ではそれが何か、作り方、編集の仕方、処分の仕方を説明します。

**入口**：プラットフォーム管理画面 → **ゲームサブセット** タブ；または分離ダイアログで「ゲームサブセット」タイプを選んで作成。

---

## 15.1 一時サブセットは何のためか

非常に大きなプラットフォームに何百何千ものゲームがあるとします。**ある種類のゲーム**にだけ何かしたい、たとえば：

- 「評価が 0.5 未満」のゲームを抽出し、まとめて直してから去就を決めたい；
- 「ある開発元」のゲームだけを取り出して新プラットフォームにしたい；
- 「ファイルが存在しない」ゲームを囲い込んで照合したい。

メインリストで藁の山から針を探すより、**一時サブセット**を使います：条件でゲームを抽出し、**独立した小さな集まり**を形成します。この小さな集まりの中でじっくり編集・検証し、最後に決めます：

| 処分方法 | 効果 |
|---|---|
| **メインセットへ同期** | サブセット内での変更を元のゲームに書き戻す（同じバッチのゲームの正式データを変更） |
| **新プラットフォームを作成** | サブセット内のゲームから全く新しいプラットフォームを起こす |
| **サブセットを削除** | この一時的な集まりだけを破棄、元のゲームには影響しない |

> 重要な理解：一時サブセットは**「草稿／一時保存」の性質**です。それ自体は正式なプラットフォームではなく、編集後は「メインセットへ同期」で反映するか、「新プラットフォームを作成」で確定するか、直接削除するかのいずれかです。

---

## 15.2 一時サブセットの作り方

一時サブセットは**プラットフォームの「分離」機能**で作成します（分離 = あるプラットフォームから条件で一部のゲームを切り出す）：

1. **プラットフォーム管理**に入り、対象プラットフォームを見つけ、行操作の **✂️ 分離** をクリック。
2. 分離ダイアログで、**分離タイプ**を **「ゲームサブセット」** に設定（もう一方は「新プラットフォーム」で、それは直接新プラットフォームに切り出す、`06` 参照）。
3. フィルタ条件を設定（下記参照）し、どのゲームが欲しいかを囲い込む。
4. 確認すると一時サブセットが生成される。

### 利用可能なフィルタ条件

分離ダイアログは多次元のフィルタを提供し、組み合わせて使えます：

| フィルタ次元 | 選択肢 |
|---|---|
| **スクレイピング状態** | スクレイピング済み / 生データあり / 低品質 / 生 ROM（複数選択可） |
| **ファイル状態** | ファイルあり / ファイルなし |
| **最低評価** | 制限なし / 0.0 ~ 1.0 |
| **発売年範囲** | 開始年 ~ 終了年 |
| **開発元** | 検索可能、Ctrl で複数選択 |
| **発売元** | 検索可能、Ctrl で複数選択 |

> 組み合わせ例：`低品質` + `ファイルあり` + `最低評価 0.5` = 「ファイルはあるが情報品質が駄目」なゲームを抽出し、集中的に手戻り。

## 15.3 サブセット内のゲームを編集

**プラットフォーム管理 → ゲームサブセット** タブ、または一時サブセット編集画面に入ると、画面はいくつかのブロックに分かれます：

1. **一時サブセットの選択**：作成済みサブセットをすべて列挙し、名前・ゲーム数・説明・作成時刻を表示。1 つクリックして選択。
2. **サブセット内のゲーム**：サブセットを選択すると、含まれるゲームを列挙（名前・ファイル名・説明の要約・ID）。あるゲームをクリックして編集へ。
3. **ゲームを編集**：フォームが現れ、これらのフィールドを変更可能：

   | フィールド | 意味 |
   |---|---|
   | ゲーム名 | name |
   | ゲームパス | path |
   | ゲーム説明 | desc |
   | 訳名 | translatedName |
   | 訳説明 | translatedDesc |
   | 開発元 | developer |
   | 発売元 | publisher |
   | ジャンル | genre |
   | プレイヤー数 | players |
   | 発売日 | releasedate |
   | 評価 | rating |
   | 言語 | lang |

   変更後 **変更を保存** をクリック。

---

## 15.4 サブセットの処分：サブセット操作

サブセットを選択すると、「サブセット操作」領域に 3 つのアクションがあります：

- **メインセットへ同期**：サブセット内のゲームへの変更を**元プラットフォームの正式ゲームデータに書き戻す**。「このバッチのゲーム自体を直したいだけ」のときに適する。
- **新プラットフォームを作成**：まず「新プラットフォーム名」に名前を入力し、サブセット内のゲームから**全く新しいプラットフォームを生成**。「このバッチを独立した 1 プラットフォームにしたい」ときに適する。
- **サブセットを削除** ⚠️：この一時的な集まり自体を削除。確認ダイアログが出る。**削除するのはサブセットというコンテナで、元のゲームは削除しない**（すでに同期していなければ）。

操作結果は画面下部の結果領域に成功／失敗のメッセージとして表示されます（約 3 秒後に自動消滅）。

## 15.5 代表的な流れ

**場面 A：低品質ゲームの一括手戻り**
1. プラットフォーム管理 → 対象プラットフォーム ✂️ 分離 → タイプ「ゲームサブセット」 → 「低品質」でフィルタ → 作成。
2. ゲームサブセット タブ → そのサブセットを選択 → ゲームごとに情報を編集 → 保存。
3. 満足したら → **メインセットへ同期**（変更が元プラットフォームに反映）。
4. 不要になったら → **サブセットを削除**。

**場面 B：新プラットフォームを切り出す**
1. 分離 → タイプ「ゲームサブセット」 → 開発元などの条件で囲い込む → 作成。
2. サブセット内でゲームを照合／微調整。
3. 新プラットフォーム名を入力 → **新プラットフォームを作成**。
4. プラットフォーム管理で新プラットフォームにシステムバインド・スクレイピング・エクスポート。

---

## 15.6 一時サブセット vs プラットフォーム統合 vs 新プラットフォームへの分離

混同しやすいので整理します：

| 機能 | 方向 | 用途 |
|---|---|---|
| **一時サブセット** | 1 プラットフォーム → ひとまとまりを抽出（一時保存） | まず囲い込み、じっくり直し、後で行き先を決める |
| **新プラットフォームへの分離** | 1 プラットフォーム → 新プラットフォームを切り出す（直接確定） | はっきり分割したい、一発で完了 |
| **プラットフォーム統合** | 複数プラットフォーム → 1 つの新プラットフォームに統合 | 散らばった同類プラットフォームをまとめる（`13` 参照） |

一時サブセットの独特な価値は「**一時保存 + 編集可能 + 複数の出口**」——「まず囲い出して直してみて、それからどうするか決める」ことができる唯一のツールです。
