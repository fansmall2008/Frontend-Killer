# 引导节点梳理（内部讨论用）

> ⚠️ **本文档性质**：这是一份**内部讨论用**的候选清单，**不是**面向用户的使用说明书章节。
> 目的：在编写使用说明书、逐个梳理功能的过程中，顺手记录"**将来可能需要对用户进行引导**"的点，方便团队日后讨论怎么设计引导系统。
> 注意：清单里的每个点都只是"**可能**需要引导"，不代表一定要做，也不代表现在就做。最终取舍留待后续讨论。

---

## 一、怎么用这份文档

- 每写完一个功能章节，就回到这里把该功能里"用户可能卡住/可能不知道/可能误操作"的点补进去。
- 每个节点按下面的**统一格式**记录，方便以后筛选、排序、评估工作量。
- 文档是**活文档**，会随说明书进度持续增长；末尾有"待评估/存疑"区收集还没想清楚的点。

---

## 二、节点记录格式

每个引导节点用如下字段描述：

| 字段 | 说明 |
|---|---|
| **编号** | `N` + 序号，便于引用（如 N03） |
| **所在页面/功能** | 用户在哪里会遇到（对应说明书章节） |
| **触发时机** | 什么情况下会到这个点（进入页面/点某按钮/某状态时） |
| **用户为什么可能卡住** | 缺什么认知、容易误解什么、容易误操作什么 |
| **可能的引导方向** | 将来可以怎么引导（气泡提示/首次向导/高亮/确认弹窗/内嵌说明等，仅作设想） |
| **节点类型** | 见下方分类 |
| **初步优先级** | 高/中/低（凭直觉先标，后续再议） |

### 节点类型分类

- **A. 首次上手**：第一次用完全不知道从哪开始
- **B. 概念理解**：术语/机制不直观，需要先理解才能操作（如刮削 vs 媒体下载）
- **C. 选择困难**：面对多个选项不知道选哪个（如模板、媒体类型、区域）
- **D. 隐藏功能**：功能存在但入口不明显，用户发现不了
- **E. 易错/危险操作**：操作不可逆或代价大，容易误触（如数据库初始化、合盘）
- **F. 流程衔接**：一步做完不知道下一步该干什么（如绑定系统后该刮削）
- **G. 异常/等待**：出错或长时间等待时用户不知道发生了什么（如限流、任务失败）

## 三、引导节点清单（按功能模块）

### 3.1 入门与全局

#### N01 · 首次启动后不知道先做什么
- **所在页面/功能**：全局 / 首页仪表盘（章节 01、02、05）
- **触发时机**：第一次打开软件，数据库是空的
- **用户为什么可能卡住**：面对空仪表盘和一堆功能入口，不知道"导入 → 绑定 → 刮削 → 导出"这条主线，容易乱点
- **可能的引导方向**：首次登录的欢迎向导 / 首页"开始使用"三步卡片 / 空状态下的行动指引
- **节点类型**：A. 首次上手 + F. 流程衔接
- **初步优先级**：高

#### N02 · ScreenScraper 凭据未配置就想刮削
- **所在页面/功能**：系统设置 / 自动刮削（章节 11、17）
- **触发时机**：用户第一次尝试刮削，但没在系统设置里填 ScreenScraper 账号
- **用户为什么可能卡住**：不知道刮削依赖外部账号；游客模式有配额限制（约 20000 次/日）但不清楚；配置入口藏在系统设置里
- **可能的引导方向**：刮削前检测凭据为空则弹提示并给"去配置"跳转 / 系统设置里高亮必填项
- **节点类型**：F. 流程衔接 + D. 隐藏功能
- **初步优先级**：高

### 3.2 平台管理

#### N03 · 平台未绑定刮削系统（★已有引导，重点参考）
- **所在页面/功能**：游戏列表页 game-list（章节 06、07）
- **触发时机**：进入某平台的游戏列表，检测到 `platform.systemId` 为空
- **用户为什么可能卡住**：不知道"平台要先绑定一个 ScreenScraper 系统才能刮削"这个前置概念
- **现状**：**软件已实现**自动弹出"系统匹配引导"弹窗（最多 5 个候选 + 命中原因 + "我自己选" + "暂不绑定" + "记住此映射"）。这是现有引导的最佳范例，新引导系统应对齐它的交互与三语规范
- **重要教训**：该功能最初做在 `platform-details.html`，因入口太隐蔽用户根本触发不到，后来迁移到高频的 `game-list.html`。**引导点的入口位置必须在用户真实路径上**
- **节点类型**：B. 概念理解 + F. 流程衔接
- **初步优先级**：高（已实现，作为标杆）

#### N04 · 绑定系统后不知道下一步要刮削
- **所在页面/功能**：平台管理 / 游戏列表（章节 06、11）
- **触发时机**：刚给平台绑定完系统
- **用户为什么可能卡住**：绑定只是"建立关系"，真正的数据要靠刮削获取，用户可能以为绑定完就有数据了
- **可能的引导方向**：绑定成功后提示"是否立即刮削" / 现有逻辑里若 `platform.scraped == 0` 且凭据已配会自动发起刮削，可加一句说明让用户知道发生了什么
- **节点类型**：F. 流程衔接 + B. 概念理解
- **初步优先级**：中

#### N05 · "临时子集"与"体量扫描"概念不直观
- **所在页面/功能**：平台管理 / 临时子集管理（章节 06、15）
- **触发时机**：平台 ROM 数量巨大，或用户想把一部分游戏单独拿出来处理
- **用户为什么可能卡住**：不理解"临时子集"是干什么的、什么时候该用；不理解体量扫描的作用
- **可能的引导方向**：功能入口旁的一句话说明 / 首次使用时的场景化提示
- **节点类型**：B. 概念理解
- **初步优先级**：中

### 3.3 游戏列表与编辑

#### N06 · 游戏状态图例（红/黄/绿）含义
- **所在页面/功能**：游戏列表管理（章节 07）
- **触发时机**：列表里游戏前面有红/黄/绿状态标记
- **用户为什么可能卡住**：不知道颜色代表数据完整度（红=无信息 / 黄=部分缺失 / 绿=完整）
- **可能的引导方向**：图例悬浮说明 / 首次进入时的图例引导
- **节点类型**：B. 概念理解
- **初步优先级**：中

#### N07 · 批量操作工具栏如何激活
- **所在页面/功能**：游戏列表管理 / 平台管理（章节 06、07）
- **触发时机**：想批量修改/删除/刮削/翻译游戏
- **用户为什么可能卡住**：不知道要先勾选条目才会出现批量工具栏；批量操作种类多（新增/删除/刮削/合盘/批量修改/翻译/迁转/切换译文/重新检测/图标类型）不易发现
- **可能的引导方向**：勾选后工具栏出现时的高亮引导 / 空列表时的操作提示
- **节点类型**：D. 隐藏功能
- **初步优先级**：中

#### N08 · 合盘（m3u）可能破坏 ROMset 完整性
- **所在页面/功能**：游戏列表管理（章节 07）
- **触发时机**：对多文件游戏执行"合盘"
- **用户为什么可能卡住**：合盘会以第一条数据为蓝本生成 m3u 并**删除原条目**，操作有代价；用户可能不清楚后果
- **可能的引导方向**：合盘前的确认弹窗说明后果 / 街机类多文件场景的特别提示
- **节点类型**：E. 易错/危险操作
- **初步优先级**：高

#### N09 · "检索游戏"模态框的用途
- **所在页面/功能**：游戏编辑（章节 08）
- **触发时机**：手动为某游戏从 ScreenScraper 找匹配数据
- **用户为什么可能卡住**：不理解什么时候需要手动检索（自动刮削没匹配上时）；不知道如何选候选
- **可能的引导方向**：编辑页的场景化说明 / 自动刮削失败后引导到手动检索
- **节点类型**：B. 概念理解 + F. 流程衔接
- **初步优先级**：中

### 3.4 数据导入

#### N10 · 不知道该选哪个导入模板
- **所在页面/功能**：数据导入（章节 09、18）
- **触发时机**：导入时要选模板（Pegasus / RetroBat / ES-DE / EmuELEC / RetroArch / Skraper 等）
- **用户为什么可能卡住**：模板名对应不同前端，用户不一定知道自己的数据属于哪种；选错模板导入结果会不对
- **可能的引导方向**：模板选择处的说明卡片（每个模板适用什么前端）/ 根据上传文件类型智能推荐
- **节点类型**：C. 选择困难
- **初步优先级**：高

#### N11 · 导入/导出前的"模板变量"弹窗不知道填什么
- **所在页面/功能**：数据导入 / 数据导出（章节 09、10、18）
- **触发时机**：选中含 `variables` 块的模板后点导入/导出，弹出变量填写框
- **用户为什么可能卡住**：不理解这些变量（如 ROM 文件夹名、URL 前缀）是干嘛的；不知道必填项；值不持久化每次都要填可能困惑
- **可能的引导方向**：弹窗内每个变量的说明已有（description 字段），可再加示例值 / 必填项校验提示
- **节点类型**：C. 选择困难 + B. 概念理解
- **初步优先级**：中

#### N12 · 媒体发现（mediaDiscovery）机制不直观
- **所在页面/功能**：数据导入（章节 09、18）
- **触发时机**：导入时希望自动从磁盘找到对应媒体文件
- **用户为什么可能卡住**：不理解导入模板会按规则在磁盘搜媒体；搜不到时不知道为什么
- **可能的引导方向**：导入结果里说明媒体发现命中情况 / 模板文档内嵌链接
- **节点类型**：B. 概念理解
- **初步优先级**：低

### 3.5 数据导出

#### N13 · 导出预检（preflight）结果怎么处理
- **所在页面/功能**：数据导出（章节 10）
- **触发时机**：导出前系统做预检，返回 `proceed` / `split` / `suggest_whole_dir` 等建议
- **用户为什么可能卡住**：不理解预检提示的含义，不知道该继续、拆分还是整目录导出
- **可能的引导方向**：预检结果的动作建议用大白话解释 + 推荐选项高亮
- **节点类型**：B. 概念理解 + C. 选择困难
- **初步优先级**：中

### 3.6 自动刮削与媒体

#### N14 · "刮削信息"与"媒体下载"是两个独立步骤
- **所在页面/功能**：自动刮削 / 媒体文件管理（章节 11、12）
- **触发时机**：用户以为刮削一次就把信息和图片都拿到了
- **用户为什么可能卡住**：1.2 起拆成"游戏信息刮削"和"媒体文件下载"两个独立进度，共用一个任务池；用户可能只做了信息刮削，纳闷为什么没图片
- **可能的引导方向**：信息刮削完成后提示"是否继续下载媒体" / 两个卡片的关系说明
- **节点类型**：B. 概念理解 + F. 流程衔接
- **初步优先级**：高

#### N15 · 媒体类型（50 种）该选哪些
- **所在页面/功能**：媒体文件管理 / 自动刮削（章节 11、12）
- **触发时机**：下载媒体时要选媒体类型
- **用户为什么可能卡住**：50 种类型（box2dfront、screenshot、video、wheel、fanart…）术语专业，不知道该勾哪些
- **可能的引导方向**：常用类型预设（如"只要封面和截图"）/ 每种类型配图示例说明
- **节点类型**：C. 选择困难
- **初步优先级**：中

#### N16 · 刮削慢/暂停——配额与限流
- **所在页面/功能**：自动刮削 / 任务管理（章节 11、14）
- **触发时机**：刮削变慢、暂停，或返回 429/430/431 限流错误
- **用户为什么可能卡住**：不理解 ScreenScraper 有配额和限流（如 10s/20 次、404 保护），以为是软件卡死
- **可能的引导方向**：限流时的状态提示"因外部配额限制暂停，将自动恢复" / 任务卡片显示原因
- **节点类型**：G. 异常/等待
- **初步优先级**：中

### 3.7 平台合并

#### N17 · 合并冲突（名称/文件/两者）如何处理
- **所在页面/功能**：平台合并（章节 13）
- **触发时机**：合并多个平台时检测到冲突
- **用户为什么可能卡住**：不理解冲突类型，不知道"添加/跳过"分别的后果；担心合并弄乱数据
- **可能的引导方向**：冲突处理弹窗的选项解释 / 合并前的影响预览 / 合并报告引导
- **节点类型**：C. 选择困难 + E. 易错操作
- **初步优先级**：中

### 3.8 任务与日志

#### N18 · 任务失败后怎么重试/看原因
- **所在页面/功能**：任务管理 / 日志查看器（章节 14、16）
- **触发时机**：任务状态变为 FAILED
- **用户为什么可能卡住**：不知道能重试、去哪看错误详情；不了解"取消"只是标记状态、长循环不一定立即停
- **可能的引导方向**：失败任务卡片直接给"重试"和"查看日志"入口 / 失败原因摘要
- **节点类型**：G. 异常/等待
- **初步优先级**：中

#### N19 · 日志查看器没有搜索/导出
- **所在页面/功能**：日志查看器（章节 16）
- **触发时机**：用户想在大量日志里找关键字
- **用户为什么可能卡住**：当前前端无内置搜索/时间筛选/导出，用户可能一直找
- **可能的引导方向**：页面提示"如需搜索请用外部工具" / 未来补内置过滤
- **节点类型**：D. 隐藏功能（能力边界）
- **初步优先级**：低

### 3.9 系统设置与个性化

#### N20 · 数据库初始化/恢复是不可逆危险操作
- **所在页面/功能**：系统设置（章节 17）
- **触发时机**：点击"初始化数据库"或"恢复数据库"
- **用户为什么可能卡住**：初始化会**删除所有业务表并清空数据**，恢复会**删除现有表**；误点后果严重
- **可能的引导方向**：强确认弹窗（输入确认词/二次确认）/ 危险区红色标识 / 操作前提示先备份
- **节点类型**：E. 易错/危险操作
- **初步优先级**：高

#### N21 · 主题切换与多语言入口
- **所在页面/功能**：系统设置 / 顶部栏（章节 03、17）
- **触发时机**：想换界面外观或语言
- **用户为什么可能卡住**：不知道主题/语言在哪切；主题包含配色+字体+音效可能不清楚
- **可能的引导方向**：顶部栏图标的首次提示
- **节点类型**：D. 隐藏功能
- **初步优先级**：低

### 3.10 模板系统（进阶）

#### N22 · 模板表达式函数太多不知道怎么下手
- **所在页面/功能**：模板系统（章节 18）
- **触发时机**：用户要自己写/改导入导出模板的表达式
- **用户为什么可能卡住**：21 个内置函数 + 运算符 + 变量体系，学习成本高；容易混淆 `map` 与 `mapFirst`、`or` 与 `+` 的优先级
- **可能的引导方向**：模板编辑处的函数速查/自动补全 / 常见配方示例库 / 错误表达式的即时校验提示
- **节点类型**：B. 概念理解 + C. 选择困难
- **初步优先级**：中（面向进阶用户）

## 三点五、现有"引导类"机制盘点（★设计新引导系统的重要参考）

> 软件里**已经存在**若干带引导性质的机制。将来做统一引导系统时，应先盘点、复用、对齐这些既有实现，避免重复造轮子或交互风格割裂。

| 编号 | 现有机制 | 位置 | 触发/形态 | 可借鉴点 |
|---|---|---|---|---|
| E1 | **系统匹配引导弹窗** | game-list.html | 进入未绑定系统的平台游戏列表时自动弹 modal，给候选+命中原因+我自己选+暂不绑定+记住映射 | 上下文自动触发、智能推荐、会话级去重（sessionStorage）、三语 i18n |
| E2 | **刮削器未就绪警告** | index.html（首页） | 进首页自检账号/系统数据，缺失则弹 SCRAPER NOT READY，带"前往配置"跳转 | 环境自检 + 一键跳转到该配置的地方 |
| E3 | **首次运行自动缓存询问** | layout.html（全局） | 仅首次弹一次，问是否启用街机游戏信息自动缓存，可稍后在设置改 | "仅一次"全局引导 + localStorage/settings 双重记录已询问 |
| E4 | **高风险操作确认弹窗** | 平台管理/游戏列表批量操作 | 批量删除、批量切换译文、合盘等执行前 confirm 二次确认并说明后果 | 危险操作的后果告知 + 取消选项 |
| E5 | **保存前文件存在性检查** | 游戏编辑保存 | 改路径后保存时检查物理文件是否存在，同步 exists 状态，前端可据此告警 | 状态实时校验反馈 |

**观察**：E1~E3 都是"上下文触发的主动引导"，E4~E5 是"操作时的即时反馈"。一套完整引导系统或许要同时覆盖这两类。E1 的会话级去重、E3 的"仅一次"记录，是引导"不打扰"策略的现成范式。

#### N23 · 首次运行的"自动缓存"询问可能看不懂
- **所在页面/功能**：全局首次运行弹窗（章节 03）
- **触发时机**：软件第一次运行，弹出"是否启用游戏信息自动缓存"
- **用户为什么可能卡住**：不理解"自动缓存""父 ROM""占用额度"这些术语，不知道怎么选
- **可能的引导方向**：弹窗内用大白话+场景说明（玩街机建议开）/ 提供"这是什么？"展开详情
- **节点类型**：B. 概念理解
- **初步优先级**：中（现已有弹窗，属文案优化）

#### N24 · 批量切换译文/批量删除后果不明
- **所在页面/功能**：平台管理、游戏列表批量工具栏（章节 06、07）
- **触发时机**：勾选多项后点"切换译文""删除"
- **用户为什么可能卡住**：切换译文会交换所有选中游戏的原文/译文，删除不可逆；用户可能不清楚影响范围
- **可能的引导方向**：现有 confirm 已说明后果，可再加"影响 N 个游戏"的量化提示 / 高危操作要求输入确认
- **节点类型**：E. 易错/危险操作
- **初步优先级**：中

### 3.11 临时子集

#### N25 · 临时子集概念抽象、三个"出口"容易选错
- **所在页面/功能**：临时子集 / 平台分离（章节 15、06）
- **触发时机**：用户第一次用分离功能，或在子集操作区面对"同步到主集/创建新平台/删除子集"三选一
- **用户为什么可能卡住**：①"临时子集"是暂存草稿这一性质不直观；②三个出口效果差别大——同步会改原游戏、创建新平台是另起、删除只删容器但用户常担心"会不会把游戏也删了"
- **可能的引导方向**：分离入口用大白话解释"先圈一批出来改"；三个出口按钮旁加一句后果说明；删除子集时明确"不会删除原游戏"
- **节点类型**：B. 概念理解 + C. 选择困难
- **初步优先级**：中

### 3.12 补充（系统设置 / 展示）

#### N26 · 列表图标字段选了却一片空白
- **所在页面/功能**：系统设置 - 游戏列表展示设置（章节 17、07）
- **触发时机**：用户把"游戏列表图标字段"改成 wheel/box-3D 等，但这些媒体还没下载
- **用户为什么可能卡住**：改完刷新发现图标全空白，以为坏了或设置没生效；页面虽有提示但容易被忽略
- **可能的引导方向**：选择某字段时若该平台/游戏普遍缺这类媒体，给出"当前多数游戏无此媒体，可能显示空白，是否先去下载"的提示 + 一键跳媒体下载
- **节点类型**：D. 隐藏功能 + G. 异常/等待
- **初步优先级**：中

#### N27 · ScreenScraper 游客模式额度用尽
- **所在页面/功能**：系统设置 - ScreenScraper 设置 / 刮削（章节 17、11）
- **触发时机**：未填账号刮削，触及游客每日约 20000 次限制
- **用户为什么可能卡住**：刮削莫名失败/变慢，不知道是额度问题，也不知道注册账号能解决
- **可能的引导方向**：刮削失败原因为额度时，提示"游客模式已达上限，配置免费账号可提升限额" + 跳转设置；现有"刮削器未就绪"警告(E2)可延伸覆盖此场景
- **节点类型**：G. 异常/等待 + F. 流程衔接
- **初步优先级**：中

### 3.13 翻译 / 导出（补充）

#### N28 · 翻译与"切换译文"机制不直观
- **所在页面/功能**：平台管理/游戏列表批量工具栏、系统设置（章节 06、07）
- **触发时机**：用户点"翻译"或"切换译文"
- **用户为什么可能卡住**：①"翻译"是生成译文字段，"切换译文"是把原文/译文对调展示，两者容易混；②翻译依赖外部 API，可能失败/耗时；③批量切换译文影响面大（已在 N24）
- **可能的引导方向**：两个按钮旁用一句区分"翻译=生成译文"/"切换=对调显示"；翻译前提示会调用外部服务、耗时与额度
- **节点类型**：B. 概念理解
- **初步优先级**：中

#### N29 · 多平台导出共享一次变量取值
- **所在页面/功能**：数据导出（章节 10）
- **触发时机**：多选平台导出时，变量弹框只弹一次
- **用户为什么可能卡住**：用户可能以为每个平台会分别问变量，实际所有平台共享同一次取值，导致某些平台路径/变量不符预期
- **可能的引导方向**：弹框时说明"本次取值将应用于所有选中平台"
- **节点类型**：C. 选择困难 + F. 流程衔接
- **初步优先级**：中

## 四、跨节点的共性观察（供设计引导系统时参考）

1. **入口位置决定成败**：N03 的教训最典型——引导做在用户到不了的页面等于没做。任何引导都要挂在用户真实高频路径上。
2. **"流程衔接"类占比高**：很多卡点不是"不会操作"，而是"做完这步不知道下一步"（N01/N04/N14）。引导系统或许应优先考虑"下一步建议"这种串联式引导，而非孤立的功能说明。
3. **危险操作需强确认**：N08（合盘）、N20（数据库初始化/恢复）不可逆，属于必须有明确警示的一类。
4. **概念性术语是理解门槛**：刮削 vs 媒体下载、临时子集、方言映射、preflight、mediaDiscovery 等，用户不先理解概念就无法正确操作。说明书承担一部分，软件内是否需要轻量解释待定。
5. **三语一致性**：现有 N03 引导已要求全部走 `data-i18n` + `I18n.t()` 三语支持。将来任何引导文案都应沿用，避免硬编码。
6. **会话级去重**：N03 用 `sessionStorage` 记录"暂不绑定"，本次会话不再弹。引导系统需要统一的"已读/不再提示"机制，避免反复打扰。
