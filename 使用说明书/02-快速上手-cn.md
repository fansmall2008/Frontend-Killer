# 02 · 快速上手

> 本章带你从零把软件跑起来，并完成第一次基础配置。跟着做即可，不需要编程基础。

---

## 2.1 你需要准备什么

- **一台能跑服务的机器**：电脑、NAS、服务器都行（Windows / macOS / Linux 均可）。
- **你的游戏 ROM 目录**：想管理的那批游戏文件，放哪由你决定。
- **ScreenScraper 账号（可选但强烈推荐）**：不填也能用（访客模式），但每天有请求上限；注册并填入账号后配额高很多。注册地址：`https://www.screenscraper.fr`。
- **Java 17+**：仅当你选择"JAR 包运行"方式时才需要。用 Docker 或 Windows EXE 则不用管 Java。

---

## 2.2 四种部署方式，选一个

软件跑起来后会监听 **8080 端口**，你用浏览器访问即可。四种方式对比：

| 方式 | 适合谁 | 优点 | 注意 |
|---|---|---|---|
| **Docker（推荐）** | NAS / 服务器 / 各系统通用 | 隔离干净、升级方便、自带健康检查 | 要正确挂载 `data` 和 `roms` 目录 |
| **Docker Compose** | 想一键启动、集中配置 | 一条命令起服务 | 注意端口占用和路径 |
| **JAR 包** | 机器上已有 Java 环境 | 不依赖 Docker | 日志/备份/权限要自己留意 |
| **Windows EXE** | Windows 用户，不想装 Java | 双击即用 | 从发布页下载对应版本 |

下面分别说。默认访问地址都是：

```
http://localhost:8080
```

（如果你把端口映射改了，比如映射到宿主机 8081，那就访问 `http://localhost:8081`。）

---

### 方式 A：Docker 部署（推荐）

**第 1 步：准备目录**
在你想放数据的目录下建两个文件夹：
- `./data`：应用数据（数据库、规则、日志、输出等）
- `./roms`：你的游戏 ROM

```bash
mkdir -p ./data ./roms
```

**第 2 步：拉取镜像**
```bash
docker pull fansmall/frontendkiller:latest
```

**第 3 步：启动容器**
```bash
docker run -d \
  --name frontend-killer \
  -p 8080:8080 \
  -v ./data:/data \
  -v ./roms:/data/roms \
  -e SPRING_PROFILES_ACTIVE=default \
  -e SERVER_TOMCAT_BASEDIR=/data \
  -e SPRING_RESOURCES_STATIC_LOCATIONS=classpath:/static/,file:/data,file:/data/roms,file:/data/output,file:/data/input \
  -e JAVA_OPTS="-Xmx2g -Xms512m -XX:+UseG1GC" \
  -e PUID=0 -e PGID=0 -e TZ=Asia/Shanghai \
  --restart unless-stopped \
  fansmall/frontendkiller:latest
```

关键参数含义：

| 参数 | 作用 |
|---|---|
| `-p 8080:8080` | 把容器 8080 端口映射到主机 8080 |
| `-v ./data:/data` | 数据目录挂载（数据库、规则等都在这，务必保留） |
| `-v ./roms:/data/roms` | 把你的 ROM 目录挂进容器 |
| `SPRING_RESOURCES_STATIC_LOCATIONS` | 允许通过网页访问 roms/output/input 里的文件 |
| `JAVA_OPTS` | 内存参数，按机器性能调整 |
| `PUID`/`PGID` | 容器运行用户，unRAID/NAS 常用 |
| `TZ` | 时区 |

**成功标志**：`docker ps` 能看到 `frontend-killer` 状态为 `Up`，浏览器打开 `http://localhost:8080` 能看到首页。

---

### 方式 B：Docker Compose

项目根目录已提供 `docker-compose.yml`（默认容器名 `webgamelistoper`，端口 8080，挂载 `./data` 和 `./roms`，含健康检查）。

```bash
docker compose up -d        # 启动
docker logs -f webgamelistoper   # 看日志
```

看到 Spring Boot 启动、暴露 8080 端口的日志后，浏览器访问 `http://localhost:8080`。

---

### 方式 C：JAR 包运行

前提：已装 **Java 17+**，已下载 `webGamelistOper-1.2.jar`。

```bash
java -jar webGamelistOper-1.2.jar
```

JAR 模式下数据目录相对"当前工作目录"：数据库在 `./data/database`、日志在 `./logs`、规则在 `./data/rules`、输入输出在 `./data/input`、`./data/output`。

---

### 方式 D：Windows EXE

1. 去 GitHub Releases 下载 EXE 安装包。
2. 解压。
3. 双击运行 `Frontend-Killer.exe`。
4. 等程序起来后，浏览器访问 `http://localhost:8080`。

---

## 2.3 首次启动后的 7 步基础配置

服务跑起来、浏览器能打开首页后，按下面顺序做一遍，就完成了从零到能用的全过程。（后面每个功能都有专门章节详解，这里只带你走通主线。）

### 第 1 步：访问主页
浏览器打开 `http://localhost:8080`。你会看到首页仪表盘，上面有多个功能卡片（导入、平台管理、导出、任务管理等），右上角可能有通知铃铛。

### 第 2 步：设置语言
进入 **系统设置与数据 → 系统设置**，在"选择语言"里选 中文 / English / 日本語，保存后刷新页面即可生效。

### 第 3 步：配置 ScreenScraper（关键）
这是能不能自动刮削的前提，**强烈建议现在就配好**。

1. 进入 **系统设置与数据 → 系统设置**，找到"ScreenScraper 设置"。
2. 填写**用户名**和**密码**（你的 ScreenScraper 账号）。
3. 点"保存设置"。
4. 点"测试连接"，确认凭据可用。
5. 点"获取系统列表"，把可刮削的主机/掌机/街机系统数据拉下来。

> 不填账号也能用（访客模式），但每天请求上限低，刮大量游戏容易被限流。
> ⚠️ 如果没配凭据就点刮削，系统会静默跳过，你可能纳闷"怎么没反应"。所以先配这里。

### 第 4 步：导入游戏数据
1. 进入 **数据导入**。
2. 选择导入模板（Pegasus、RetroBat、ES-DE 等，选和你数据来源匹配的）。
3. 选择游戏列表文件，或直接扫描 ROM 目录。
4. 按需勾选"匹配未记录媒体文件"。
5. 点"开始扫描并导入"。

导入完成后会显示统计，"平台管理"里就能看到新平台。

> 不知道选哪个模板？见 `09 数据导入` 和 `18 模板系统详解`。

### 第 5 步：绑定系统并刮削
1. 进入 **数据处理 → 平台管理**。
2. 找到你的平台，点"编辑"，给它**选一个匹配的 ScreenScraper 系统**并保存。
3. 点平台行的"刮削"按钮，在弹窗里确认媒体范围，点"开始刮削"。
4. 刮削任务进入后台队列，去 **任务管理** 页看进度。

> 提示：打开某平台的游戏列表时，如果它还没绑定系统，软件会自动弹出"系统匹配引导"帮你选（见 `06 平台管理`）。

### 第 6 步：编辑游戏（可选）
1. 平台管理里点平台名进入 **游戏列表**。
2. 点某个游戏进入 **游戏编辑**。
3. 改名称、描述、翻译等；也可点"搜索游戏"手动补充 ScreenScraper 数据。
4. 点"保存更改"。

### 第 7 步：导出数据
1. 进入 **数据导出**。
2. 选要导出的平台。
3. 选目标前端格式（Pegasus、ES-DE 等）。
4. 勾选导出内容：游戏文件 / 媒体文件 / 数据文件。
5. 指定输出目录，点"导出"。

导出完成后，输出目录里会出现数据文件（如 `gamelist.xml`）和相关媒体，可直接给前端使用。任务状态在 **任务管理** 里看。

## 2.4 装不起来？先自查这几条

| 现象 | 常见原因 | 怎么办 |
|---|---|---|
| 浏览器打不开 `localhost:8080` | 端口被占用 / 映射错 / 容器没起来 | `docker ps` 看状态；`docker logs frontend-killer` 看报错；端口冲突就改 `-p 8081:8080` 再访问 8081 |
| Docker 起来后没数据/规则 | 首次启动 `/data` 为空，会自动释放初始数据 | 看日志确认 entrypoint 是否执行了规则复制；检查 `/data` 是否存在 |
| ScreenScraper 连接失败 | 账号密码错 / 网络不通 / 配额用尽 | 重填凭据→测试连接；确认能访问 screenscraper.fr；必要时注册账号提配额 |
| 导入后找不到 ROM/媒体 | ROM 目录没挂载 / 模板和目录结构不匹配 | 确认 `-v ./roms:/data/roms`；确认模板选对；确认静态资源路径含 roms 目录 |
| 数据库损坏/想重置 | —— | 系统设置里可"备份/恢复/初始化"。**初始化会清空数据、不可逆，务必先备份** |

更完整的排查见 `19 常见问题与故障排除`。
