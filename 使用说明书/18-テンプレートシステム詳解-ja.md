# 18 · テンプレートシステム詳解

> インポート／エクスポート時、ソフトウェアは「テンプレート規則」に依拠して、各フィールドの値の取り方、ファイル名、どのディレクトリに置くかを決めます。テンプレートには**式**を書けます——フィールド参照、文字列連結、関数呼び出し。本章はテンプレートシステムの完全リファレンスです：変数、演算子、全 21 個の組み込み関数、レシピ例とトラブル対処。

**適用場面**：インポート規則（`rules/import/`）、エクスポート規則（`rules/export/`）内のフィールドマッピング、ファイル名、パステンプレートを編集するとき。

---

## 18.1 まず「フィールド名」と「式」を区別する

テンプレートに入れる値は 2 種類：

- **素のフィールド名**：例 `name`、`desc`、`box-2D`。そのゲームフィールドの値を直接取り、何も加工しない。
- **式**：**関数呼び出しの括弧 `()`**、**プラス `+`**、**`or` 演算子**（前後に空白）、または**引用符で始まる**ものを含むと、式として計算される。

例：
- `name` → 素のフィールド、ゲーム名を取る。
- `name or filename` → 式（or あり）、名前が空ならファイル名にフォールバック。
- `stem(path) + ".jpg"` → 式（関数と + あり）、拡張子を除いたファイル名を取り `.jpg` を付ける。

**文字列リテラル**はダブルクォートまたはシングルクォートで囲む：`"hello"`、`'.jpg'`。

## 18.3 演算子

演算子は 2 つだけで、**優先度は低い順**：

| 演算子 | 意味 | 優先度 |
|---|---|---|
| `or` | **フォールバック**——最初の非空値を取る（SQL の COALESCE 的） | 低 |
| `+` | **文字列連結** | 高 |

`+` の優先度が `or` より高いため：

- `name or filename + ".jpg"` は `name or (filename + ".jpg")` に等しい——name に値があれば name を使う（.jpg なし）、なければ filename+".jpg" を使う。
- 両方にサフィックスを付けたいなら括弧を付ける：`(name or filename) + ".jpg"`。

`or` キーワードは**前後に空白が必要**（または先頭／末尾）。さもないと演算子として扱われません——これにより `color`、`order` のような "or" を含むフィールド名が誤判定されません。

多段フォールバック例：`box-2D or screenshot or image`（順に最初にあるメディアを探す）。

## 18.4 全 21 個の組み込み関数

カテゴリ別に列挙。シグネチャ内の `str`/`path` はまず評価される式を表します。

### A. 文字列操作（11 個）

| 関数 | シグネチャ | 説明 |
|---|---|---|
| `sub` | `sub(str, start[, end])` | 部分文字列。start は 0 始まり；end を省略すると末尾まで。範囲外は自動クランプ |
| `upper` | `upper(str)` | 大文字に変換 |
| `lower` | `lower(str)` | 小文字に変換 |
| `trim` | `trim(str)` | 前後の空白を除去 |
| `replace` | `replace(str, from, to)` | from をすべて to に置換 |
| `before` | `before(str, sep)` | 区切りの**前**の部分を取る；区切りがなければ元の文字列を返す |
| `after` | `after(str, sep)` | 区切りの**後**の部分を取る；区切りがなければ元の文字列を返す |
| `concat` | `concat(f1, f2, ...)` | 全引数を連結、**空値をスキップ** |
| `sanitize` | `sanitize(str, charset)` | charset に現れる各文字を `_` に置換（不正ファイル名文字の掃除用） |
| `matches` | `matches(str, regex)` | 正規表現の**完全一致**、`"true"`/`"false"` を返す |
| `len` | `len(str)` | 文字列長を返す（数値文字列） |

例：
- `sub(name, 0, 7)` → 名前の先頭 7 文字を取る。
- `upper(stem(path))` → ファイル名（拡張子なし）を大文字に。
- `trim(replace(name, " ", "_"))` → 空白をアンダースコアに置換してから前後空白を除去（ネスト可）。
- `before(name, "(")` → 最初の `(` の前の部分を取る（"(USA)" のようなサフィックスを落とす前によく使う）。
- `after(path, "/")` → 最初の `/` の後を取る。
- `sanitize(name, "<>\"/\\|?*")` → Windows の不正ファイル名文字をすべて `_` に置換。
- `if(matches(genre, ".*Racing.*"), "レース", "その他")` → if と組み合わせて条件に。

### B. パス操作（4 個）

| 関数 | シグネチャ | 説明 |
|---|---|---|
| `filename` | `filename(path)` | パスから**ファイル名（拡張子付き）**を取る |
| `stem` | `stem(path)` | ファイル名を取り**拡張子を除去** |
| `ext` | `ext(path)` | **拡張子（ドット付き）**を取る、例 `.zip`；なければ空 |
| `dir` | `dir(path)` | **ディレクトリ部分**（親パス）を取る |

例：`stem(path) + ext(path)` で完全なファイル名を復元；`dir(path)` で所在ディレクトリを取得。

> 区別に注意：パス関数 `filename(path)` は**拡張子付き**のファイル名を返す；一方、計算フィールド `filename`（括弧なし）は**拡張子なし**のファイル名を返す。両者は異なるので混同しないこと。

### C. 条件 / デフォルト値（3 個、遅延評価）

| 関数 | シグネチャ | 説明 |
|---|---|---|
| `default` | `default(field, fallback)` | field が空なら fallback を使う |
| `if` | `if(cond, trueVal[, falseVal])` | cond が非空かつ `"false"` でなければ真とみなし trueVal、そうでなければ falseVal を返す |
| `coalesce` | `coalesce(f1, f2, ...)` | 最初の非空値を返す（`or` チェーンの関数形） |

この 3 つは**遅延評価**：必要な分岐だけを計算し、不要なオーバーヘッド／エラーを避けます。

例：
- `default(desc, "説明なし")`。
- `if(multiFile, m3uPath, filename(path))` → 複数ファイルは m3u 名、それ以外はファイル名。
- `coalesce(translatedName, name, filename)` → 訳名優先、次に原名、最後にファイル名。

> `if` の真偽の約束：文字列 `"false"`（大文字小文字無視）と空文字列は偽、他の非空値は真——`matches` の返り値とちょうど噛み合います。

### D. 日付操作（1 個）

| 関数 | シグネチャ | 説明 |
|---|---|---|
| `dateformat` | `dateformat(dateStr, pattern)` | 日付を pattern で再フォーマット |

- 複数の入力形式を自動認識：`yyyy-MM-dd'T'HH:mm:ss`、`yyyy-MM-dd HH:mm:ss`、`yyyy-MM-dd`、`yyyyMMdd`、`yyyy`、`MM/dd/yyyy`、`dd/MM/yyyy`。
- 解析できないときは**入力そのままを返し**、エラーになりません。
- pattern は Java の `SimpleDateFormat` 構文（`yyyy` 年、`MM` 月、`dd` 日）。

例：`dateformat(releasedate, "yyyy")` → 年だけ取る；`dateformat(releasedate, "yyyy-MM")`。

### E. 方言マッピング（2 個）

ScreenScraper の生の語（英語の genre、システム名など）を、望むローカライズ／カスタム語にマップするのに使います。マップテーブルは `term_mapping`（`rules/translation-config.json` などで保守）、`genre`、`system_alias` などのカテゴリに分かれます。

| 関数 | シグネチャ | 説明 |
|---|---|---|
| `map` | `map(value[, category])` | マップテーブルを照会し、ヒットすれば対象語を返し、**ヒットしなければそのまま返す** |
| `mapFirst` | `mapFirst(value[, category])` | 同上だが、複数値のとき**最初の 1 つだけ**を返す |

規則の詳細：
- category を指定しない：**`system_alias` 以外**の全カテゴリで照会（system_alias はシステムマッチングの内部用途）；同一値が複数カテゴリにヒットしたときはカテゴリ名の辞書順で最初を取る（結果を確定させる）。
- category を指定：そのカテゴリのみで照会、例 `map(genre, "genre")`。
- 照会前に値を**正規化**（小文字化、空白と句読点を除去）するので、`"Beat'em Up"` / `"beat em up"` / `"beatemup"` は等価。
- **複数値の処理**（値にカンマを含む、例 `"Racing, Driving"`）：
  - `map`：各セグメントをマップし、全結果を `-` で連結。
  - `mapFirst`：まず値全体をマップし、駄目なら分割して最初の有効結果を取る——ディレクトリ名など単一値が欲しい場面に適する。

例：`map(genre)` で英語ジャンルを自国語に；`mapFirst(genre)` で主ジャンルだけ。

## 18.5 総合レシピ例

**安全なファイル名**
```
sanitize(stem(path), "<>\"/\\|?*")
```
拡張子を除去 + 不正文字を掃除し、ファイル名に安全に使える文字列を得る。

**メディア多段フォールバック + サフィックス**
```
(box-2D or screenshot or image) + ".png"
```

**エクスポートディレクトリをプラットフォーム／年で階層化**
```
platform.name + "/" + dateformat(releasedate, "yyyy") + "/" + name
```

**ジャンルのローカライズ**
```
map(genre, "genre")
```

**複数ファイルゲームの特別処理**
```
if(multiFile, m3uPath, filename(path))
```

**名前に括弧サフィックスがあるとき主名を取る**
```
trim(before(name, "("))
```

**空値のフォールバック**
```
coalesce(translatedName, name, filename, "不明なゲーム")
```

## 18.6 よくあるエラーと調査

| 現象 | 原因 | 解決 |
|---|---|---|
| 式がそのまま出力／値が取れない | 式であるべきがトリガー条件を欠く（`()`/`+`/`or`/引用符がない）、素のフィールド名として扱われた | 関数の括弧や引用符の漏れを確認 |
| `or` が効かない | `or` の前後に空白がない、またはフィールド名自体に "or" を含む | `or` の両側に空白を置く |
| 連結とフォールバックの結果が期待と違う | `+` の優先度が `or` より高い | 括弧で順序を明示 `(a or b) + ".ext"` |
| `filename` の結果がおかしい | 関数 `filename(path)`（拡張子付き）とフィールド `filename`（拡張子なし）を混同 | 必要に応じて選択；拡張子を落とすなら `stem` |
| `map` がマップされない | 値が正規化後にヒットしない / カテゴリ違い / テーブルにその項目がない | `term_mapping` に対応項目があるか確認；必要なら category を指定 |
| `dateformat` がそのまま返す | 入力日付形式が認識可能リストにない | まず日付形式を整える、または pattern を変える |
| 式全体が失敗して空を返す | 構文エラー（括弧／引用符の不対応など）、エンジンは warn ログを記録し null を返す | ログビューアで "式評価失敗" の warn を確認（`16` 参照） |

> エンジンは式の評価失敗に対し**フォールトトレラント**です：エラーを投げず、warn ログを 1 件記録して空値を返すだけです。したがってあるフィールドが不可解に空になったら、まずログで式の警告がないか見てください。

## 18.7 インポート・エクスポートとの関係

- **インポート規則**（`rules/import/`）：データファイルからフィールドをどう読んでゲームに入れるかを定義。
- **エクスポート規則**（`rules/export/`）：エクスポート時のファイル名・ディレクトリ・データファイルフィールドの生成方法を定義。
- フロントエンド（Pegasus、EmulationStation など）ごとにテンプレートの制限があり、エクスポート画面に黄色い注意が出ます（`10` 参照）。

テンプレート式はこれらの規則の「計算の中核」で、インポートとエクスポートは同一エンジンを共有し、構文は完全に一致します。
