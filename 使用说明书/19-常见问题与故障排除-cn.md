## 19.2 页面打不开 / 无法访问

**现象**：浏览器访问 `http://localhost:8080`（或你的部署地址）打不开、白屏、连接被拒。

**排查**：
1. **软件是否在运行**：确认 jar/exe/Docker 容器已启动，控制台没有报错退出。
2. **端口**：默认 `8080`。若被别的程序占用，改 `application.properties` 里的 `server.port`，或关掉占用端口的程序。
3. **地址对不对**：本机用 `localhost`；Docker/NAS 部署要用**主机 IP + 映射端口**，不是 localhost。
4. **目录权限**：`data`、`output`、`logs`、`backup` 目录要可读写（NAS/容器常见坑）。
5. 看启动日志有没有 "Cannot connect to database"、"Address already in use" 等字样（见 19.12）。

## 19.3 刮削失败、刮不到信息

**现象**：发起刮削后，游戏没获得信息，或任务变红 FAILED。

**常见原因与对策**：

| 原因 | 判断 | 解决 |
|---|---|---|
| **平台没绑定系统** | 平台 systemId 为空 | 进游戏列表会弹系统匹配引导，或去平台管理 ✏️ 编辑绑定（见 `06`、19.8） |
| **刮削账号没配** | 首页弹"刮削器未就绪" | 系统设置填 ScreenScraper 账号 → 测试连接 → 获取系统列表（见 `17`） |
| **游戏名太乱匹配不到** | 名字含大量标签/编号 | 先规整游戏名，或用游戏编辑里的手动检索指定（见 `08`） |
| **ScreenScraper 没这条** | 冷门/自制游戏 | 属正常，手动补信息 |
| **网络/限流** | 日志有 Timeout、Rate limit | 稍后重试，见 19.5 |

> 刮削是"信息（文字）"，媒体（图片视频）是**另一步**，要去媒体下载页单独下（见 `12`）。刮到信息不等于有图。

## 19.4 媒体下载很慢 / 老暂停 / 停住

**现象**：媒体下载进度走得慢，时不时停一下，感觉卡住。

**多半是保护机制在起作用，属正常**：
- **并发默认 3 个**，不会全速猛下。
- **限流保护**：对 ScreenScraper 请求有节流（约 10 秒 20 次量级）。
- **404 熔断**：连续找不到资源会短时退避（约 10 秒 10 次量级）。
- **去重**：下过的不重复下，所以后面的看着"没动"其实是跳过了。

**对策**：
- 别反复手动重启，让它自己跑。
- 可在媒体下载页调整**并发线程**适当提速（但太高易触发限流，适得其反）。
- 真失败的项去**任务管理**重试（见 `14`）。
- 想临时让路给别的任务 → 面板里**暂停**，事后**恢复**。

## 19.5 提示额度用尽 / 429 / 401

ScreenScraper 用状态码告诉你出了什么事：

| 状态码 | 含义 | 怎么办 |
|---|---|---|
| **401 / 认证失败** | 账号或密码不对、没登录 | 系统设置重新填正确账号 → 测试连接（见 `17`） |
| **429 / 限流** | 请求太频繁触发限制 | **暂停任务，等一会儿**再恢复；降低并发 |
| **游客额度用尽** | 没配账号，每日约 20000 次触顶 | 注册免费账号填进去提升限额（见 `17`、N27） |
| **5xx / 服务端错误** | ScreenScraper 那边的问题 | 不是你的错，过一阵重试 |

> 遇到限流，"等 + 降并发 + 重试"三板斧。硬刚只会一直被挡。

## 19.6 导入没反应、找不到文件

**现象**：点了导入，扫不到游戏，或提示找不到文件。

**排查**：
1. **扫描层级选对没**：数据导入页有第 1~4 层复选框，**只扫勾选的那一层**，不会自动往下钻子文件夹。ROM 放得深就要勾对应层级（见 `09`）。
2. **ROM 目录对不对**：确认 `roms/`（或你指定的路径）下真的有文件。
3. **导入方式**：模板方式 vs 无数据文件导入，选错会读不到（见 `09`）。
4. **媒体没关联**：想让导入带上无记录的媒体文件，要勾"匹配无记录媒体文件"（mediaDiscovery）。
5. 看任务管理和日志有没有报错。

---

## 19.7 导出路径不对、导不出

**现象**：导出后找不到文件，或提示路径问题。

**排查**：
1. **导出路径**：默认 `/data/output`（Docker）或你设置的 outputPath。确认这个目录**存在且可写**。
2. **平台文件夹路径**：合并/导出常需要平台有文件夹路径，缺了会在预检（preflight）提示（见 `10`、`13`）。
3. **preflight 预检提示**：导出前会检查，可能给出 proceed（继续）/ split（拆分）/ suggest_whole_dir（建议整目录）等选项，按提示选。
4. **导出范围**：勾了"游戏文件/媒体文件/数据文件"里的哪些？没勾媒体就不会带图片（见 `10`）。
5. **前端模板限制**：某些前端对字段/结构有限制，导出页会有黄色提示。

## 19.8 平台无法刮削、没系统

**现象**：平台刮削不了，或游戏列表进来就弹一个选系统的框。

**说明**：这是**系统匹配引导**（现有机制 E1）——平台没绑定 ScreenScraper 系统时自动弹，让你从候选里选。

**对策**：
- 从候选里选一个，或点"我自己选"手动挑，或"记住此映射"以后自动匹配。
- 暂时不想弄点"暂不绑定"（本次会话不再弹）。
- 也可在平台管理 ✏️ 编辑里手动绑定系统（见 `06`）。
- **前提**：系统设置里已"获取系统列表"，否则没有候选（见 `17`）。

## 19.9 任务卡住、取消不停

**现象**：任务一直 RUNNING，点了取消还在跑。

**说明**：目前"取消"是把任务**标记为已取消**，长时间运行的循环不一定立刻停（要循环内检查点才真断），所以取消后可能还跑一小会儿。

**对策**：
- 稍等片刻看状态是否转 CANCELLED。
- 媒体下载用面板的**停止**按钮。
- 软件异常关闭后重启，会做**任务恢复**：把残留 RUNNING 标记为 FAILED、DOWNLOADING 重置为 PENDING（见 `14`）。重启后看到任务变红/回队列是正常的，重试即可。

## 19.10 数据误删 / 搞砸了想回退

**现象**：批量删错、合并搞乱、初始化清空了数据。

**对策**：
- **有备份**：系统设置 → 数据库备份区 → 选一个备份**恢复**（会用备份覆盖当前数据，见 `17`）。
- **没备份**：初始化/删除是**不可逆**的，很难找回。这正是为什么我们反复强调——**做大操作前先备份**（合并、批量删除、恢复、初始化前）。
- 养成习惯：每次要动大数据前，先点一下"备份数据库"。

> ⚠️ "执行初始化"会重建表结构并清空所有数据，不可逆。除非确实要清空重来，否则别点（见 `17`、N20）。

## 19.11 语言 / 主题 / 图标没生效

| 现象 | 原因 | 解决 |
|---|---|---|
| 切了语言没变 | 语言需刷新页面才生效 | 刷新页面（见 `17`） |
| 切了列表图标字段一片空白 | 该游戏没有所选类型的媒体 | 先去媒体下载对应类型，或换回 image（见 `17`、N26） |
| 主题没变 | 没点选主题卡片 / 需刷新 | 重新选主题包，刷新 |

## 19.12 怎么用日志定位问题

日志是排查的第一手线索（详见 `16`）：

1. 打开 **日志查看器** 📊，或看 `logs/application.log`。
2. 优先找 **ERROR / WARN** 行。
3. 常见关键字：`ERROR`、`Timeout`、`Connection refused`、`Rate limit`、`Authentication failed`、`Cannot connect to database`、`表达式计算失败`。
4. 定位到出错那几行，往上翻 INFO 看它之前在做什么操作。
5. 页面没有内置搜索，用浏览器 Ctrl+F 或直接打开日志文件搜。

## 19.13 求助时该提供什么

反馈问题给别人（社区/issue）时，带上这些能大幅加快定位：

- **做了什么操作**：如"对 XX 平台发起刮削"、"导出到 /data/output"。
- **看到的现象/报错文字**：原样复制，别只说"失败了"。
- **相关日志片段**：ERROR 前后几行 + 时间。
- **环境**：部署方式（jar/exe/Docker/NAS）、版本（v1.2）、操作系统。
- **是否配了 ScreenScraper 账号**（涉及刮削时）。

> 一句"刮削坏了"很难帮上忙；"对 PS2 平台刮削，任务 FAILED，日志报 429 Rate limit"就能立刻定位。

## 19.14 还是不行？

- 回对应功能章节再看一遍操作流程（`05`~`18`）。
- 确认前提条件：刮削要账号 + 系统列表；导出要文件夹路径；导入要扫描层级。
- 保守起见，排查前先**备份数据库**，避免越弄越糟。
