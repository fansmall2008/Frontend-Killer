# 04 · エンドツーエンドの流れ

> 本章では個々の機能の詳細ではなく、**最初から最後まで完全な主線を一通り**辿り、「これらの機能がどうつながって使われるか」を理解させます。各工程に対応する詳述の章を明記しているので、深掘りしたいときにそこへ飛んでください。

---

## 4.1 一枚の図で主線を把握

```
 ① 準備          ② インポート       ③ システムバインド     ④ 情報スクレイピング
 ROM/データ →  プラットフォームへ  →  プラットフォーム↔SS  →  文字資料を補完
                                                        ↓
 ⑦ エクスポート   ⑥ 編集・整理        ⑤ メディアDL
 フロントエンドへ ←  修正/翻訳/統合  ←   画像・動画を補完
```

7 つの工程：
1. **準備**：ROM や既存フロントエンドのデータファイルを用意。
2. **インポート**：データをソフトウェアに読み込み、「プラットフォーム + ゲームリスト」を形成。
3. **システムバインド**：このプラットフォームが ScreenScraper のどの標準システムに対応するかを伝える。
4. **情報スクレイピング**：ゲームの名前・紹介文・発売元・ジャンル・日付などの文字資料を自動補完。
5. **メディアダウンロード**：カバー・スクリーンショット・動画などの画像／動画を自動ダウンロード。
6. **編集・整理**：誤りの手動修正、翻訳、複数ディスクゲームの統合、一括調整。
7. **エクスポート**：対象フロントエンドが要求する形式で書き出し、そのままエミュレータで使う。

以下、工程ごとに説明します。

---

## ① 準備：まず ROM かデータを用意

以下のどちらか（または両方）が必要です：

- **ROM ファイル一式**：あるディレクトリに置く（Docker デプロイでは通常マウントした `roms` ディレクトリ）。
- **既存フロントエンドのデータファイル**：たとえば以前 Pegasus / ES-DE / RetroBat で生成したゲームリストファイル（`metadata.pegasus.txt`、`gamelist.xml` など）とメディアフォルダ。

同時に確認：ScreenScraper アカウントを **システム設定** で設定済みか（さもないと工程 ④⑤ で自動スクレイピングできません）。→ `02 クイックスタート` のステップ 3。

---

## ② インポート：データを読み込む

**入口**：サイドバー **データインポート** 📥 → 詳述 `09 データインポート`

代表的な 2 つのインポート方式：

- **テンプレートインポート**：既にフロントエンドのデータファイルがある場合、対応テンプレート（Pegasus / ES-DE / RetroBat / EmuELEC など）を選ぶと、ソフトウェアがテンプレート規則に沿ってファイルを解析し、ゲームとメディアパスを読み込みます。
- **データファイルなしインポート（ROM スキャン）**：ROM だけでデータファイルがない場合、ROM ディレクトリを直接スキャンし、各 ROM に対しゲーム項目を作成します（資料はまず空で、スクレイピングで補完）。

インポート時には次のことが起きる可能性があります：
- **テンプレート変数**入力ダイアログが出る（ROM フォルダ名、URL プレフィックスなど）ので、説明どおり入力。
- **メディア発見**（mediaDiscovery）が起動し、ディスク上の既存画像／動画を規則に沿ってゲームに自動照合。

**成果**：データベースに「プラットフォーム」と、その配下の「ゲーム」が新規追加されます。**プラットフォーム管理** 🎮 で新しいプラットフォームが見えます。

---

## ③ システムバインド：プラットフォームと ScreenScraper システムを対応付ける

**入口**：**プラットフォーム管理** → プラットフォームを編集 → スクレイピングシステムを選択；またはプラットフォームのゲームリストを直接開いて誘導を起動 → 詳述 `06 プラットフォーム管理`

**なぜ必須か**：ScreenScraper は「標準システム」（PS1、Saturn、MAME…）単位でデータを整理しています。あなたのプラットフォームはシステムに**バインド**することで、ソフトウェアはデータベースのどのゲーム機で資料を引けばよいかを知ります。**バインドしていないと自動スクレイピングはできません。**

**便利な点**：**まだシステムにバインドしていない**プラットフォームのゲームリストを開くと、ソフトウェアは**自動で「システムマッチング誘導」を出し**、プラットフォームのフォルダ名や拡張子などから最も可能性の高い数システムを賢く推薦します。押すだけでバインドでき、「自分で選ぶ」や「今はバインドしない」も可能です。バインド後は「このマッピングを記憶」をチェックでき、次回同名フォルダは自動でヒットします。

---

## ④ 情報スクレイピング：文字資料を補完

**入口**：プラットフォーム管理 → プラットフォーム行の「スクレイピング」ボタン；またはゲームリストで一括スクレイピング → 詳述 `11 自動スクレイピング`

スクレイピングは ScreenScraper に接続し、各ゲームについて名前・紹介文・発売元・開発元・発売日・ジャンル・プレイヤー数・評価などの**文字資料**を引いてきます。

**要点（多くの人が躓く）**：1.2 以降、「スクレイピング」は**2 つの独立ステップ**に分かれます——
- このステップは**情報（文字）**だけをスクレイピングします。
- 画像／動画は**次のステップの別個の「メディアダウンロード」**です。

したがって情報をスクレイピングした後に「なぜカバーがないのか」と気づくのは正常で、メディアは別途ダウンロードが必要です（⑤ 参照）。

スクレイピングタスクはバックグラウンドキューに入り、**タスク管理** 📋 で進捗を確認、完了後は右上の**通知ベル**が知らせます。

---

## ⑤ メディアダウンロード：画像・動画を補完

**入口**：サイドバー **メディアダウンロード** 🖼️、またはタスク管理内のメディアダウンロードパネル → 詳述 `12 メディアファイル管理`

このステップでカバー（box-2D）、スクリーンショット（ss）、動画（video）、ロゴ（wheel）、背景画像（fanart）などの**メディアファイル**をダウンロードします。ScreenScraper には **50 種のメディアタイプ**があり、必要な数種だけ選べます（よく使うのは：カバー + スクリーンショット）。

メディアファイルは `data/scraper/games/{システム}/{ゲーム}/` にダウンロードされ、データベースには相対パスが記録されます。

**注意**：
- メディアダウンロードには並行制限（既定 3）とレート制限保護があり、速度が遅いのは正常なので焦らないでください。
- 404 やレート制限に当たると、ソフトウェアは自動でバックオフ・リトライします。
- ダウンロードタスクも同様に **タスク管理** で一時停止／再開／停止／リトライできます。

---

## ⑥ 編集・整理：必要に応じて修正

**入口**：プラットフォーム管理 → プラットフォームをクリック → **ゲームリスト** → ゲームをクリック → **ゲーム編集** → 詳述 `07 ゲームリスト管理`、`08 ゲーム編集`

スクレイピングで戻った資料は 100% 正確とは限らず、このステップで修正・強化します：

- **個別編集**：ゲーム編集ページに入り、名前／説明／ジャンルなどを変更。4 つのタブ（基本情報 / メタデータ / メディア管理 / メディアプレビュー）。自動スクレイピングでマッチしなかったゲームは「ゲーム検索」で ScreenScraper から手動で探せます。
- **一括操作**：ゲームリストで複数ゲームをチェックし、フィールド一括変更、一括翻訳、一括再スクレイピング、訳文切替、ディスク統合（複数ディスクを m3u に統合）など。
- **状態が一目瞭然**：ゲームリストは赤／黄／緑でデータの完全度を示します（赤=情報なし、黄=一部欠落、緑=完全）。赤と黄を優先処理するのに便利。
- **翻訳**：資料を対象言語に翻訳できます（`17` 参照）。

> ⚠️ ディスク統合は元の独立項目を削除し、ROMset の完全性に影響する可能性があります。操作前によく考えてください。

---

## ⑦ エクスポート：フロントエンドで使う

**入口**：サイドバー **データエクスポート** 📤 → 詳述 `10 データエクスポート`

整理が終わったら、データを対象フロントエンドで使える形式に書き出します：

1. エクスポートするプラットフォームを選ぶ（単一または一括）。
2. 対象フロントエンドテンプレートを選ぶ（Pegasus / ES-DE / RetroBat など）。
3. エクスポート内容をチェック：**ゲームファイル（ROM）/ メディアファイル / データファイル**。
4. 出力ディレクトリを指定。
5. エクスポート前にソフトウェアが**プリフライト（preflight）**を行い、提案（直接エクスポート / 分割 / ディレクトリ全体を推奨）を出すので、指示に従って処理。
6. エクスポートを押すとタスクがキューに入り、**タスク管理** で進捗を確認。

**成果**：出力ディレクトリにデータファイル（`gamelist.xml`、`metadata.pegasus.txt` など）+ 整頓された ROM とメディアが生成され、そのままフロントエンドにコピーすれば使えます。

---

## 4.2 全工程を貫く 2 つの「ボード」

どの工程に進んでも、この 2 か所が常に全体把握を助けます：

- **ホームのダッシュボード** 🏠（詳述 `05`）：プラットフォーム総数、ゲーム総数、スクレイピングカバー率、スクレイピング段階別（スクレイピング済み／生データ／低品質／生 ROM）、システム状態、実行中タスクを見る。
- **タスク管理** 📋（詳述 `14`）：すべてのバックグラウンドタスクの状態と進捗を見て、停止・キャンセル・削除・リトライができ、メディアダウンロードも制御できる。

---

## 4.3 完全な例（つなげて見る）

セガ Saturn の ROM が一式あり、ES-DE で使える画像付きゲームライブラリにしたいとします：

1. **準備**：ROM を `roms/saturn/` に置き、ScreenScraper アカウントを設定。
2. **インポート**：データインポート → 「ROM ディレクトリをスキャン」または ES-DE テンプレートを選択 → プラットフォームを生成。
3. **バインド**：そのプラットフォームのゲームリストを開く → 自動でマッチング誘導が出る → "Sega Saturn" を選んでバインド（「このマッピングを記憶」もチェック可）。
4. **情報スクレイピング**：プラットフォーム管理 → 該当プラットフォーム → スクレイピング → 開始、タスク完了を待つ。
5. **メディアダウンロード**：メディアダウンロード → カバー+スクリーンショットを選択 → ダウンロード開始。
6. **編集**：ゲームリストで赤／黄のものを処理し、マッチしなかった個別は手動検索、中国語が必要なら翻訳。
7. **エクスポート**：データエクスポート → 該当プラットフォーム → ES-DE テンプレート → ROM+メディア+データをチェック → ディレクトリ指定 → エクスポート。
8. 出力ディレクトリを ES-DE にコピーすれば、起動時に画像付きのゲームリストが見られます。
