# 09 · Data Import

> Import is the first step to "move" your games into the software. You can import from an existing frontend's data files, or scan a ROM directory directly. This chapter clarifies how to choose between the two methods and what each option means.

**Entry**: sidebar **Data Import** 📥 (DATA group)

---

## 9.1 Two Import Methods

The page has an **"Import method"** dropdown with two options:

| Method | When to use |
|---|---|
| **Template method** (default) | You already have a **data file** generated by some frontend (e.g., `gamelist.xml`, `metadata.pegasus.txt`) and want to read it in along with games and media paths |
| **No-data-file import** | You **only have a pile of ROM files**, no data file, and want the software to scan the directory and create a game entry per ROM (data left empty, filled later by scraping) |

---

## 9.2 Scan Path Settings

Either way, first tell the software where to scan:

- **Scan root path**: enter the directory to import (where the ROMs or data files are).
- **Scan levels**: check level 1 / 2 / 3 / 4.
  - ⚠️ Key understanding: **A checked level only scans files directly in that level's directory; it does not automatically descend into subfolders.**
  - Level 1 is the root path you entered; to import games in deeper subfolders, check the corresponding deeper level.
  - Example: games placed directly under the root path → check level 1; one folder per console under the root, games inside those folders → check level 2.

---

## 9.3 Template Method: Pick the Right Template

After choosing "Template method", pick an **"Import template"**. The template determines how the software parses your data file. Common templates map to different frontends:

| Template | Frontend/scenario |
|---|---|
| **Pegasus** | Pegasus Frontend (`metadata.pegasus.txt`) |
| **ES-DE / EmulationStation** | ES-DE (`gamelist.xml`) |
| **RetroBat** | RetroBat (Windows frontend) |
| **EmuELEC** | EmuELEC (`gamelist.xml` + `downloaded_images`) |
| **RetroArch** | RetroArch (lpl playlists / folder style) |
| **Skraper-ES** | Data Skraper generated for ES |

> **Picking the wrong template imports incorrectly.** How to judge: look at what your data file looks like and which frontend generated it, then pick the matching template. If unsure, see the template notes in `18 Template System Guide`.

An import template internally defines: how fields map (gameInfo), how media maps (mediaInfo), and optional **media discovery rules** (mediaDiscovery), etc. These are v3 template contents; ordinary users just pick a ready-made template, while advanced users can customize (see `18`).

---

## 9.4 The "Match Unrecorded Media Files" Option

The page has a checkbox: **"Match unrecorded media files (scan disk per template rules)"**, meaning:

- **Checked**: Fully execute the template, including **mediaDiscovery rules** — the software proactively searches the disk for images/videos by rule, so even if the data file doesn't record them, existing media can be matched to games.
- **Unchecked**: Only process media paths **already declared** in the data file, skipping the disk scan.

> When to check it? If your media files are scattered on disk and not fully listed in the data file, checking it helps auto-complete media associations.

### What is media discovery (mediaDiscovery)
A template can configure a set of rules to "find media on disk by filename rules". For example, for the game `supermario.nes`, it looks in order for `media/supermario/boxFront.png`, `boxFront/supermario.png`, etc. If found, it auto-associates to the corresponding media type. This is a v3 template capability; ordinary users enjoy it via ready-made templates.

---

## 9.5 Multi-file Games & Computed Variables (FYI)

- **Multi-file game detection**: During import the software can recognize multi-disc/multi-file games (e.g., lpl playlists, ROMs inside ZIPs) and expand them as needed.
- **Computed variables**: Import templates auto-inject variables like `filename` and `filepath` (path without extension and `./` prefix) for template expressions (see `18`).

Ordinary users needn't worry about these details — just pick the right template.

---

## 9.6 Template Variable Dialog

If your chosen template declares **variables the user must fill** (a variables block, e.g., ROM subfolder name, URL prefix), clicking start import **pops up an input dialog** listing, per item: variable name, input box, description.

- Fill per the description; those marked "required" can't be left empty.
- Variable values are **not saved** — you re-enter them each import.

> Unsure what to enter? Read the description under each item; it explains the variable's purpose. (This is also a potential guidance point we've recorded.)

---

## 9.7 Start Import

Once set, click **"Start scan and import"**.

- Import runs as a background task; watch progress in **Task Management** 📋 (see `14`).
- When done, import statistics are shown and platforms/games are added to the database.
- Go to **Platform Management** 🎮 to see the new platform.

---

## 9.8 Common Post-Import Issues

| Symptom | Possible cause | What to do |
|---|---|---|
| No games after import | Wrong scan level, wrong path | Confirm the level is checked right (see 9.2) and the path is correct |
| Can't find ROMs/media | ROM dir not mounted / template mismatch | In Docker confirm the mount; use the right template |
| Media not associated | Didn't check "match unrecorded media files" | Check it and re-import, or review mediaDiscovery rules |
| Fields misaligned/garbled | Template doesn't match data file format | Switch to the correct template |

More in `19 FAQ & Troubleshooting`.
