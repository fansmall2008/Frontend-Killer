# 02 · クイックスタート

> 本章では、ゼロからソフトウェアを起動し、最初の基本設定を完了するまでを案内します。手順どおりに進めればよく、プログラミングの知識は不要です。

---

## 2.1 準備するもの

- **サービスを動かせるマシン**：PC、NAS、サーバーのいずれでも可（Windows / macOS / Linux すべて OK）。
- **ゲーム ROM ディレクトリ**：管理したいゲームファイル一式。置く場所は自由です。
- **ScreenScraper アカウント（任意だが強く推奨）**：入力しなくても使えます（ゲストモード）が、1 日あたりのリクエスト上限があります。登録してアカウントを入力すると割り当てが大きく増えます。登録先：`https://www.screenscraper.fr`。
- **Java 17+**：「JAR パッケージ実行」方式を選ぶ場合のみ必要。Docker や Windows EXE なら Java は不要です。

---

## 2.2 4 つのデプロイ方式から 1 つ選ぶ

ソフトウェアは起動後 **8080 ポート**をリッスンし、ブラウザからアクセスします。4 方式の比較：

| 方式 | 誰に向くか | メリット | 注意 |
|---|---|---|---|
| **Docker（推奨）** | NAS / サーバー / 各 OS 共通 | 分離がクリーン、アップグレードが容易、ヘルスチェック内蔵 | `data` と `roms` ディレクトリを正しくマウントすること |
| **Docker Compose** | ワンクリック起動・設定集約したい人 | 1 コマンドでサービス起動 | ポート占有とパスに注意 |
| **JAR パッケージ** | マシンに Java 環境が既にある人 | Docker に依存しない | ログ／バックアップ／権限は自分で留意 |
| **Windows EXE** | Windows ユーザーで Java を入れたくない人 | ダブルクリックで即利用 | リリースページから対応版をダウンロード |

以下でそれぞれ説明します。既定のアクセス先はいずれも：

```
http://localhost:8080
```

（ポートマッピングを変えた場合、たとえばホストの 8081 にマップしたら `http://localhost:8081` にアクセスします。）

---

### 方式 A：Docker デプロイ（推奨）

**ステップ 1：ディレクトリ準備**
データを置きたいディレクトリに 2 つのフォルダを作ります：
- `./data`：アプリデータ（データベース・規則・ログ・出力など）
- `./roms`：ゲーム ROM

```bash
mkdir -p ./data ./roms
```

**ステップ 2：イメージ取得**
```bash
docker pull fansmall/frontendkiller:latest
```

**ステップ 3：コンテナ起動**
```bash
docker run -d \
  --name frontend-killer \
  -p 8080:8080 \
  -v ./data:/data \
  -v ./roms:/data/roms \
  -e SPRING_PROFILES_ACTIVE=default \
  -e SERVER_TOMCAT_BASEDIR=/data \
  -e SPRING_RESOURCES_STATIC_LOCATIONS=classpath:/static/,file:/data,file:/data/roms,file:/data/output,file:/data/input \
  -e JAVA_OPTS="-Xmx2g -Xms512m -XX:+UseG1GC" \
  -e PUID=0 -e PGID=0 -e TZ=Asia/Shanghai \
  --restart unless-stopped \
  fansmall/frontendkiller:latest
```

主要パラメータの意味：

| パラメータ | 役割 |
|---|---|
| `-p 8080:8080` | コンテナの 8080 ポートをホストの 8080 にマップ |
| `-v ./data:/data` | データディレクトリのマウント（データベース・規則などすべてここ。必ず保持） |
| `-v ./roms:/data/roms` | ROM ディレクトリをコンテナにマウント |
| `SPRING_RESOURCES_STATIC_LOCATIONS` | roms/output/input 内のファイルを Web からアクセス可能にする |
| `JAVA_OPTS` | メモリパラメータ。マシンの性能に応じて調整 |
| `PUID`/`PGID` | コンテナ実行ユーザー。unRAID/NAS でよく使う |
| `TZ` | タイムゾーン |

**成功の目安**：`docker ps` で `frontend-killer` の状態が `Up` になり、ブラウザで `http://localhost:8080` を開くとトップページが見えます。

---

### 方式 B：Docker Compose

プロジェクトルートに `docker-compose.yml` を用意済み（既定のコンテナ名 `webgamelistoper`、ポート 8080、`./data` と `./roms` をマウント、ヘルスチェック付き）。

```bash
docker compose up -d        # 起動
docker logs -f webgamelistoper   # ログ確認
```

Spring Boot の起動・8080 ポート公開のログが見えたら、ブラウザで `http://localhost:8080` にアクセスします。

---

### 方式 C：JAR パッケージ実行

前提：**Java 17+** がインストール済みで、`webGamelistOper-1.2.jar` をダウンロード済み。

```bash
java -jar webGamelistOper-1.2.jar
```

JAR モードではデータディレクトリは「現在の作業ディレクトリ」からの相対です：データベースは `./data/database`、ログは `./logs`、規則は `./data/rules`、入出力は `./data/input`、`./data/output`。

---

### 方式 D：Windows EXE

1. GitHub Releases から EXE インストーラをダウンロード。
2. 解凍。
3. `Frontend-Killer.exe` をダブルクリックで実行。
4. プログラムが起動したら、ブラウザで `http://localhost:8080` にアクセス。

---

## 2.3 初回起動後の 7 ステップ基本設定

サービスが起動しブラウザでトップページが開けるようになったら、以下の順序で一通り行えば、ゼロから使える状態まで完了します（各機能は以降の章で詳述するので、ここでは主線だけ通します）。

### ステップ 1：トップページにアクセス
ブラウザで `http://localhost:8080` を開きます。トップページのダッシュボードが表示され、複数の機能カード（インポート・プラットフォーム管理・エクスポート・タスク管理など）と、右上に通知ベルがあるかもしれません。

### ステップ 2：言語を設定
**システム設定とデータ → システム設定**に入り、「言語の選択」で 中文 / English / 日本語 を選び、保存後にページを再読み込みすると反映されます。

### ステップ 3：ScreenScraper を設定（重要）
これは自動スクレイピング可否の前提なので、**今すぐ設定することを強く推奨**します。

1. **システム設定とデータ → システム設定**に入り、「ScreenScraper 設定」を見つけます。
2. **ユーザー名**と**パスワード**（あなたの ScreenScraper アカウント）を入力。
3. 「設定を保存」をクリック。
4. 「接続テスト」をクリックし、認証情報が使えることを確認。
5. 「システム一覧の取得」をクリックし、スクレイピング可能なゲーム機／携帯機／アーケードのシステムデータを取得。

> アカウントを入力しなくても使えます（ゲストモード）が、1 日あたりのリクエスト上限が低く、大量のゲームをスクレイピングすると制限されやすいです。
> ⚠️ 認証情報を設定せずにスクレイピングを押すと、システムは静かにスキップし、「なぜ反応しないのか」と困惑するかもしれません。だから先にここを設定しましょう。

### ステップ 4：ゲームデータをインポート
1. **データインポート**に入る。
2. インポートテンプレートを選択（Pegasus、RetroBat、ES-DE など、データの出所と合うもの）。
3. ゲームリストファイルを選ぶか、ROM ディレクトリを直接スキャン。
4. 必要に応じて「未記録メディアファイルの照合」をチェック。
5. 「スキャンしてインポートを開始」をクリック。

インポート完了後に統計が表示され、「プラットフォーム管理」で新しいプラットフォームが見えます。

> どのテンプレートを選ぶか分からない？→ `09 データインポート` と `18 テンプレートシステム詳解`。

### ステップ 5：システムをバインドしてスクレイピング
1. **データ処理 → プラットフォーム管理**に入る。
2. プラットフォームを見つけ「編集」を押し、**合う ScreenScraper システムを 1 つ選んで**保存。
3. プラットフォーム行の「スクレイピング」ボタンを押し、ダイアログでメディア範囲を確認して「スクレイピングを開始」。
4. スクレイピングタスクはバックグラウンドキューに入るので、**タスク管理**ページで進捗を見る。

> ヒント：あるプラットフォームのゲームリストを開いたとき、まだシステムにバインドしていなければ、ソフトウェアは自動で「システムマッチング誘導」を出して選択を手伝います（`06 プラットフォーム管理`参照）。

### ステップ 6：ゲームを編集（任意）
1. プラットフォーム管理でプラットフォーム名を押し **ゲームリスト**に入る。
2. あるゲームを押して **ゲーム編集**に入る。
3. 名前・説明・翻訳などを変更。「ゲーム検索」を押して ScreenScraper データを手動補完することも可能。
4. 「変更を保存」をクリック。

### ステップ 7：データをエクスポート
1. **データエクスポート**に入る。
2. エクスポートするプラットフォームを選ぶ。
3. 対象フロントエンド形式を選ぶ（Pegasus、ES-DE など）。
4. エクスポート内容をチェック：ゲームファイル / メディアファイル / データファイル。
5. 出力ディレクトリを指定し、「エクスポート」をクリック。

エクスポート完了後、出力ディレクトリにデータファイル（`gamelist.xml` など）と関連メディアが現れ、そのままフロントエンドで使えます。タスク状態は **タスク管理** で確認します。

## 2.4 起動できない？まずこの数項目を自己点検

| 現象 | よくある原因 | 対処 |
|---|---|---|
| ブラウザで `localhost:8080` が開けない | ポート占有 / マップ誤り / コンテナ未起動 | `docker ps` で状態確認、`docker logs frontend-killer` でエラー確認、ポート競合なら `-p 8081:8080` に変えて 8081 にアクセス |
| Docker 起動後にデータ／規則がない | 初回起動時 `/data` が空だと初期データを自動展開 | ログで entrypoint が規則コピーを実行したか確認、`/data` が存在するか確認 |
| ScreenScraper 接続失敗 | アカウント／パスワード誤り / ネット不通 / 割り当て枯渇 | 認証情報を再入力→接続テスト、screenscraper.fr にアクセスできるか確認、必要ならアカウント登録で割り当て増 |
| インポート後に ROM／メディアが見つからない | ROM ディレクトリ未マウント / テンプレートとディレクトリ構造の不一致 | `-v ./roms:/data/roms` を確認、テンプレートの選択を確認、静的リソースパスに roms ディレクトリが含まれるか確認 |
| データベース破損／リセットしたい | —— | システム設定で「バックアップ／復元／初期化」が可能。**初期化はデータを消去し元に戻せないため、必ず先にバックアップ** |

より完全なトラブル対処は `19 よくある質問とトラブル対処`。
