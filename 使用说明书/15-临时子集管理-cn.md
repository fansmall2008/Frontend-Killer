# 15 · 临时子集管理

> 临时子集（游戏子集）是从某个平台里"筛出来的一小撮游戏"的临时集合。你可以先按条件圈一批游戏、逐个改，改好后再决定是同步回主集、还是另存为一个新平台。本章讲它是什么、怎么创建、怎么编辑、怎么处置。

**入口**：平台管理页 → **游戏子集** tab；或分离弹窗里选"游戏子集"类型创建。

---

## 15.1 临时子集是干什么的

想象你有一个很大的平台，里面游戏成百上千。你只想**针对某一类游戏**做点事，比如：

- 把"评分低于 0.5"的游戏挑出来，统一改一改再决定去留；
- 把"某个开发商"的游戏单独拎出来，做成一个新平台；
- 把"文件不存在"的游戏圈出来核对。

与其在主列表里大海捞针，不如用**临时子集**：按条件筛出一批游戏，形成一个**独立的小集合**。在这个小集合里可以慢慢编辑、验证，最后再决定：

| 处置方式 | 效果 |
|---|---|
| **同步到主集** | 把子集里的修改写回原来的游戏（改的是同一批游戏的正式数据） |
| **创建新平台** | 用子集里的游戏另起一个全新平台 |
| **删除子集** | 只是丢掉这个临时集合，不影响原游戏 |

> 关键理解：临时子集是**"草稿/暂存"性质**。它本身不是正式平台，改完要么"同步回主集"生效，要么"创建新平台"落地，要么直接删掉。

---

## 15.2 怎么创建一个临时子集

临时子集通过**平台的"分离"功能**创建（分离 = 从一个平台里按条件拆出一部分游戏）：

1. 进 **平台管理**，找到目标平台，点行操作里的 **✂️ 分离**。
2. 在分离弹窗里，**分离类型**选 **"游戏子集"**（另一种是"新平台"，那是直接拆成新平台，见 `06`）。
3. 设置筛选条件（见下节），圈定要哪些游戏。
4. 确认后生成一个临时子集。

### 可用的筛选条件

分离弹窗提供多维度筛选，可组合使用：

| 筛选维度 | 选项 |
|---|---|
| **刮削状态** | 已刮削 / 有原始数据 / 质量差 / 纯ROM（可多选） |
| **文件状态** | 文件存在 / 文件不存在 |
| **最低评分** | 不限制 / 0.0 ~ 1.0 |
| **发行年份范围** | 开始年份 ~ 结束年份 |
| **开发商** | 可搜索、Ctrl 多选 |
| **发行商** | 可搜索、Ctrl 多选 |

> 组合示例：`质量差` + `文件存在` + `最低评分 0.5` = 挑出"有文件但信息质量不行"的游戏，集中返工。

## 15.3 编辑子集里的游戏

进入 **平台管理 → 游戏子集** tab，或临时子集修改页，界面分几块：

1. **选择临时子集**：列出所有已创建的子集，显示名称、游戏数量、描述、创建时间。点一个选中它。
2. **子集中的游戏**：选中子集后，列出它包含的游戏（名称、文件名、描述摘要、ID）。点某个游戏进入编辑。
3. **编辑游戏**：出现一张表单，可改这些字段：

   | 字段 | 说明 |
   |---|---|
   | 游戏名称 | name |
   | 游戏路径 | path |
   | 游戏描述 | desc |
   | 翻译名称 | translatedName |
   | 翻译描述 | translatedDesc |
   | 开发商 | developer |
   | 发行商 | publisher |
   | 游戏类型 | genre |
   | 玩家数 | players |
   | 发布日期 | releasedate |
   | 评分 | rating |
   | 语言 | lang |

   改完点 **保存修改**。

---

## 15.4 处置子集：子集操作

选中子集后，"子集操作"区有三个动作：

- **同步到主集**：把子集里对游戏的修改**写回原平台的正式游戏数据**。适合"我就是想改这批游戏本身"。
- **创建新平台**：需要先在"新平台名称"里填名字，然后把子集里的游戏**生成一个全新平台**。适合"这批游戏我想独立成一个平台"。
- **删除子集** ⚠️：删除这个临时集合本身。会有确认弹窗。**删的是子集这个容器，不会删除原游戏**（除非你已经同步过）。

操作结果会在页面下方的结果区显示成功/失败提示（约 3 秒后自动消失）。

---

## 15.5 典型流程

**场景 A：批量返工低质量游戏**
1. 平台管理 → 目标平台 ✂️ 分离 → 类型选"游戏子集" → 筛"质量差" → 创建。
2. 游戏子集 tab → 选中该子集 → 逐个游戏改信息 → 保存。
3. 改满意后 → **同步到主集**（修改生效到原平台）。
4. 不再需要就 **删除子集**。

**场景 B：拆一个新平台出来**
1. 分离 → 类型"游戏子集" → 按开发商等条件圈定 → 创建。
2. 子集里核对/微调游戏。
3. 填新平台名称 → **创建新平台**。
4. 去平台管理给新平台绑定系统、刮削、导出。

---

## 15.6 临时子集 vs 平台合并 vs 分离新平台

容易混，理一下：

| 功能 | 方向 | 用途 |
|---|---|---|
| **临时子集** | 一个平台 → 筛出一批（暂存） | 先圈定、慢慢改、再决定去向 |
| **分离为新平台** | 一个平台 → 拆出新平台（直接落地） | 明确要拆分，一步到位 |
| **平台合并** | 多个平台 → 合成一个新平台 | 把分散的同类平台归拢（见 `13`） |

临时子集的独特价值在于"**暂存 + 可编辑 + 多出口**"——它是唯一一个能让你"先圈出来改改看、再决定怎么办"的工具。
