## 19.2 ページが開けない / アクセスできない

**現象**：ブラウザで `http://localhost:8080`（またはあなたのデプロイ先アドレス）が開けない、白画面、接続拒否。

**調査**：
1. **ソフトウェアが動いているか**：jar/exe/Docker コンテナが起動し、コンソールがエラーで終了していないか確認。
2. **ポート**：既定は `8080`。他のプログラムに占有されていたら、`application.properties` の `server.port` を変えるか、ポートを占有するプログラムを終了。
3. **アドレスは正しいか**：ローカルマシンは `localhost`；Docker/NAS デプロイは **ホスト IP + マップ済みポート**を使い、localhost ではない。
4. **ディレクトリ権限**：`data`、`output`、`logs`、`backup` ディレクトリは読み書き可能であること（NAS/コンテナでよくある落とし穴）。
5. 起動ログに "Cannot connect to database"、"Address already in use" などの文言がないか見る（19.12 参照）。

## 19.3 スクレイピング失敗、情報が取れない

**現象**：スクレイピングを開始したが、ゲームに情報が付かない、またはタスクが赤く FAILED になる。

**よくある原因と対策**：

| 原因 | 見分け方 | 解決 |
|---|---|---|
| **プラットフォームがシステム未バインド** | プラットフォームの systemId が空 | ゲームリストに入るとシステムマッチング誘導が出る、またはプラットフォーム管理 ✏️ 編集でバインド（`06`、19.8 参照） |
| **スクレイピングアカウント未設定** | ホームに「スクレイパー準備未完」が出る | システム設定で ScreenScraper アカウントを入力 → 接続テスト → システム一覧の取得（`17` 参照） |
| **ゲーム名が乱雑でマッチしない** | 名前に大量のタグ／番号を含む | まずゲーム名を整える、またはゲーム編集の手動検索で指定（`08` 参照） |
| **ScreenScraper にその項目がない** | マイナー／自作ゲーム | 正常——手動で情報を補完 |
| **ネットワーク／レート制限** | ログに Timeout、Rate limit | 後でリトライ、19.5 参照 |

> スクレイピングは「情報（文字）」で、メディア（画像・動画）は**別のステップ**です。メディアダウンロード画面で別途ダウンロードが必要です（`12` 参照）。情報をスクレイピングしても画像があるとは限りません。

---

## 19.4 メディアダウンロードが遅い / すぐ止まる / 固まる

**現象**：メディアダウンロードの進捗が遅く、時々止まり、固まったように感じる。

**多くは保護機構が働いており、正常です**：
- **並行は既定 3 件**で、全力ではダウンロードしない。
- **レート制限保護**：ScreenScraper へのリクエストにスロットリング（約 10 秒に 20 回のオーダー）。
- **404 サーキットブレーカー**：連続でリソースが見つからないと短時間バックオフ（約 10 秒に 10 回のオーダー）。
- **重複排除**：ダウンロード済みは再ダウンロードしないので、後半は「動いていない」ように見えて実はスキップしている。

**対策**：
- 繰り返し手動で再起動せず、自動で走らせる。
- メディアダウンロード画面で**並行スレッド**を調整してある程度高速化できる（が高すぎるとレート制限を招き逆効果）。
- 本当に失敗した項目は**タスク管理**でリトライ（`14` 参照）。
- 一時的に他のタスクへ譲りたい → パネルで**一時停止**、後で**再開**。

## 19.5 割り当て枯渇 / 429 / 401 の表示

ScreenScraper はステータスコードで何が起きたかを伝えます：

| ステータスコード | 意味 | どうするか |
|---|---|---|
| **401 / 認証失敗** | アカウントやパスワードが違う、未ログイン | システム設定で正しいアカウントを再入力 → 接続テスト（`17` 参照） |
| **429 / レート制限** | リクエストが頻繁すぎて制限に到達 | **タスクを一時停止し、しばらく待って**から再開；並行を下げる |
| **ゲスト割り当て枯渇** | アカウント未設定、1 日約 20000 回に到達 | 無料アカウントを登録して入力し制限を上げる（`17`、N27 参照） |
| **5xx / サーバー側エラー** | ScreenScraper 側の問題 | あなたのせいではない、しばらくしてリトライ |

> レート制限に当たったら「待つ + 並行を下げる + リトライ」の三段構え。強引に押してもブロックされ続けます。

## 19.6 インポートが反応しない、ファイルが見つからない

**現象**：インポートを押したがゲームがスキャンされない、またはファイルが見つからないと表示。

**調査**：
1. **スキャン階層は正しいか**：データインポート画面に第 1~4 層のチェックボックスがあり、**チェックした層だけをスキャン**し、自動でサブフォルダに潜りません。ROM を深く置いているなら対応する層をチェック（`09` 参照）。
2. **ROM ディレクトリは正しいか**：`roms/`（または指定パス）に本当にファイルがあるか確認。
3. **インポート方式**：テンプレート方式 vs データファイルなしインポート、間違えると読み込めない（`09` 参照）。
4. **メディアが関連付かない**：インポートに記録のないメディアファイルを含めたいなら、「未記録メディアファイルの照合」をチェック（mediaDiscovery）。
5. タスク管理とログにエラーがないか見る。

## 19.7 エクスポートパスが違う、エクスポートできない

**現象**：エクスポート後にファイルが見つからない、またはパスの問題を表示。

**調査**：
1. **エクスポートパス**：既定は `/data/output`（Docker）または設定した outputPath。このディレクトリが**存在し書き込み可能**か確認。
2. **プラットフォームフォルダパス**：統合／エクスポートはプラットフォームにフォルダパスが必要なことが多く、欠けているとプリフライト（preflight）で促されます（`10`、`13` 参照）。
3. **プリフライトの注意**：エクスポート前にチェックし、proceed（続行）/ split（分割）/ suggest_whole_dir（ディレクトリ全体を推奨）などの選択肢を出すことがあるので、指示に従う。
4. **エクスポート範囲**：「ゲームファイル／メディアファイル／データファイル」のどれをチェックした？メディアをチェックしなければ画像は付かない（`10` 参照）。
5. **フロントエンドテンプレートの制限**：一部のフロントエンドはフィールド／構造に制限があり、エクスポート画面に黄色い注意が出る。

## 19.8 プラットフォームがスクレイピングできない、システムがない

**現象**：プラットフォームがスクレイピングできない、またはゲームリストに入った途端にシステムを選ぶボックスが出る。

**説明**：これは**システムマッチング誘導**（既存機構 E1）です——プラットフォームが ScreenScraper システムにバインドしていないとき自動で出て、候補から選ばせます。

**対策**：
- 候補から 1 つ選ぶ、または「自分で選ぶ」で手動選択、または「このマッピングを記憶」で以後自動マッチ。
- 今はやりたくなければ「今はバインドしない」（今回のセッションでは再度出ない）。
- プラットフォーム管理 ✏️ 編集で手動バインドも可能（`06` 参照）。
- **前提**：システム設定で「システム一覧の取得」済みであること、さもないと候補がない（`17` 参照）。

## 19.9 タスクが固まる、キャンセルしても止まらない

**現象**：タスクがずっと RUNNING で、キャンセルを押してもまだ動いている。

**説明**：現在「キャンセル」はタスクを**キャンセル済みとマークする**もので、長時間実行されるループは直ちに止まらないことがあります（真に中断するにはループ内にチェックポイントが必要）。したがってキャンセル後も少し動くことがあります。

**対策**：
- 少し待って状態が CANCELLED に変わるか見る。
- メディアダウンロードはパネルの**停止**ボタンを使う。
- ソフトウェアの異常終了後に再起動すると**タスク回復**を行います：残った RUNNING を FAILED にマークし、DOWNLOADING を PENDING にリセット（`14` 参照）。再起動後にタスクが赤くなる／キューに戻るのは正常で、リトライすれば OK。

## 19.10 データを誤削除 / 失敗して戻したい

**現象**：一括削除を誤った、統合が乱れた、初期化でデータを消した。

**対策**：
- **バックアップがある**：システム設定 → データベースバックアップ領域 → バックアップを 1 つ選んで**復元**（バックアップで現在のデータを上書きする、`17` 参照）。
- **バックアップがない**：初期化／削除は**元に戻せず**、取り戻すのは非常に困難。だからこそ繰り返し強調します——**大きな操作の前にバックアップ**（統合・一括削除・復元・初期化の前）。
- 習慣にする：大きなデータを触るたびに、まず「データベースをバックアップ」を押す。

> ⚠️ 「初期化を実行」はテーブル構造を再構築し全データを消去、元に戻せません。本当に消してやり直したいとき以外は押さないでください（`17`、N20 参照）。

## 19.11 言語 / テーマ / アイコンが反映されない

| 現象 | 原因 | 解決 |
|---|---|---|
| 言語を切り替えても変わらない | 言語はページ再読み込みで反映 | ページを再読み込み（`17` 参照） |
| リストアイコンフィールドを切り替えて一面空白 | そのゲームに選択したタイプのメディアがない | まずそのメディアタイプをダウンロード、または image に戻す（`17`、N26 参照） |
| テーマが変わらない | テーマカードを押していない / 再読み込みが必要 | テーマパックを選び直し、再読み込み |

## 19.12 ログで問題を特定する方法

ログは調査の第一手の手がかりです（詳述 `16`）：

1. **ログビューア** 📊 を開く、または `logs/application.log` を見る。
2. まず **ERROR / WARN** 行を探す。
3. よくあるキーワード：`ERROR`、`Timeout`、`Connection refused`、`Rate limit`、`Authentication failed`、`Cannot connect to database`、`式評価失敗`。
4. エラーの数行を特定し、上の INFO を遡ってその前に何をしていたか見る。
5. 画面に組み込み検索はないので、ブラウザの Ctrl+F を使うか、ログファイルを直接開いて検索。

## 19.13 助けを求めるときに提供すべきもの

他人（コミュニティ／issue）に問題を報告するとき、これらを添えると特定が大きく速くなります：

- **何の操作をしたか**：例「XX プラットフォームにスクレイピングを開始」「/data/output にエクスポート」。
- **見た現象／エラー文言**：そのままコピー、「失敗した」だけでは駄目。
- **関連ログの抜粋**：ERROR 前後の数行 + 時刻。
- **環境**：デプロイ方式（jar/exe/Docker/NAS）、バージョン（v1.2）、OS。
- **ScreenScraper アカウントを設定したか**（スクレイピングが関わるとき）。

> 一言「スクレイピングが壊れた」では助けにくい；「PS2 プラットフォームをスクレイピング、タスク FAILED、ログに 429 Rate limit」なら即座に特定できます。

## 19.14 それでも駄目なら？

- 対応する機能の章に戻って操作フローを再確認（`05`~`18`）。
- 前提条件を確認：スクレイピングはアカウント + システム一覧；エクスポートはフォルダパス；インポートはスキャン階層。
- 念のため、調査の前に**データベースをバックアップ**し、余計に悪化させないようにする。
